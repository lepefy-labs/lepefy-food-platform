# Growth prospecting: research, contacts and suppression

Platform-owner tool to find shops that could become Lepefy tenants, contact them
one by one and keep a trace of every exchange. Lepefy never sends anything: the
platform owner sends each message from their own WhatsApp or e-mail.

## Pieces

| Piece | Where | Role |
| --- | --- | --- |
| Research | Claude Code session with a browser + `growth/` CLI | Discovery, verification of sources, dossiers (`growth/AGENT.md`) |
| Engine | `growth/src/qualify.mjs`, `identity.mjs`, `config/features.json` | Single source of truth: signals from opened sources, fit, entry route, message lint, identity keys |
| Engine copy | `apps/storefront/src/lib/growth/engine/` | Generated by `node growth/scripts/sync-engine.mjs`; `tests/unit/growthProspecting.spec.ts` fails when stale. Never edit the copy |
| Import | `node growth/cli.mjs push` → `POST /api/internal/growth/ingest` | Bearer `GROWTH_INGEST_TOKEN` (≥ 32 chars); the server re-evaluates every dossier, refuses rejected ones, never writes sales fields |
| Data | migration `185_growth_prospecting.sql` | `growth_prospects`, append-only `growth_prospect_touches`, `growth_suppressions`; RLS forced, no policy, service role only |
| Page | `/admin/platform/prospection` (+ `/[id]`) | Platform owner only (`requirePlatformOwner`), absent from `adminApiPermissions.ts` |

`growth/data/` (names, addresses, public phone numbers) is git-ignored: the
repository is public. It lives on the researcher's machine and in the database.

## Contact rules (`lib/growth/contactPolicy.ts`, unit-tested)

- WhatsApp and e-mail open the owner's app with a prefilled text (`wa.me/<digits>?text=`, `mailto:`). The page asks « Le message est-il parti ? » and records the contact only on yes, with the exact text.
- Written channels always carry the opt-out sentence in the message language (`withOptOut`); the touches API refuses a written first message without it.
- Cold WhatsApp only in France. Elsewhere (Italy in particular) a first contact in person or by phone comes first. To be confirmed by legal counsel before scaling.
- Warnings: the number is probably the customers' order line (`chatOrders` confirmed), already followed up twice, more than 10 WhatsApp messages today (account restriction risk). Use a dedicated Lepefy WhatsApp Business number.
- Blocked: « do not contact », refused (`perso`), already a client.
- The message is re-linted with the same engine as the CLI (sourced facts, one question, no promise, length per channel).

## Stages and suppression

- `sales_stage` follows the recorded outcome (`stageAfterTouch`): `da_contattare → contattato → in_conversazione → demo → cliente`, `perso` on a refusal. It never moves backwards except a refusal, and a reply after a refusal.
- « Ne plus contacter » (with a reason) suppresses every strong identity key of the shop (domain, social handle, phone, VAT). An import of a dossier matching a suppressed key arrives already excluded; `push` downloads the keys to `growth/data/suppressions.json` and the CLI refuses those shops on `ingest` and lists them in `brief`.

## Operations

```bash
node growth/scripts/sync-engine.mjs            # after any change in growth/src or growth/config/features.json
GROWTH_INGEST_URL=https://<admin host>/api/internal/growth/ingest GROWTH_INGEST_TOKEN=… node growth/cli.mjs push
node growth/cli.mjs push --dry-run             # counts what would be sent
```

Before the first push: apply migration 185 and set `GROWTH_INGEST_TOKEN` in the Vercel project (and locally for the CLI).
